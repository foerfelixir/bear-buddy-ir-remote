Troubleshooting

Most failures are supply voltage, button state, debugger mode, or a weak IR LED—not the protocol constants.

Chip not detected

  1. Confirm 3.3 V at VDD and common ground.
  2. Put WCH-LinkE in WCH-LinkRV / RISC-V mode.
  3. Connect SWIO (PD1) and SWCLK (PD3).
  4. For configurable or Samsung builds, hold any button immediately before Detect/Program.
  5. Power-cycle if a prior SWIO session left the MCU awake.

Link drops during programming

  • Keep a button held; SWIO movement extends the six-second window.
  • Use a fresh cell or regulated 3.3 V supply.
  • Shorten debugger leads and keep SWCLK/SWIO away from the IR LED wiring.
  • Do not load code while the battery booster is sagging.

NEC 200 ms offers only a three-second startup window and no post-release window.

Firmware runs, no IR output

  1. Check button inputs: pressing should pull the pin to ground.
  2. Check PA2 with a scope or an IR receiver. Confirm the output is active-low.
  3. Inspect the NPN transistor, 1 kΩ base resistor, 47 Ω LED resistor, and LED polarity.
  4. Try a phone camera to confirm carrier activity.
  5. Confirm you flashed the intended variant at 0x08000000.

Samsung device ignores a key

  • Different Samsung generations use different protocol families. This build emits Samsung32.
  • For Power/Enter, the first full frame should work even before repeats.
  • For SW3, wait for the full 7 → 1 → 5 → 0 → Enter sequence.
  • Verify the target expects Samsung address 7.

Wrong configurable behavior

  • Blank or corrupt IRC2 pages deliberately fall back to factory NEC commands.
  • Program the full 2112-byte template before patching config.
  • Magic must be IRC2; protocol values are 0 or 1.
  • The checksum covers only bytes 0x00..0x0F.

Configuration layout

Do not confuse a working IR build with an unreachable SWIO link

A pressed button wakes the firmware and keeps the link window open. Release it only after Detect/Program completes. If the chip vanishes afterward, power-cycle and reconnect before retrying.
